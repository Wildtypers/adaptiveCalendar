Database Schema Design
Purpose

The purpose of the database schema design is to define how Predictive Planner stores, organizes, and retrieves application data.

The database serves three primary purposes:

Store user tasks and scheduling information.
Act as the source of truth for application state.
Collect historical user behavior data to improve personalized predictions.

The schema is designed to support the MVP while maintaining flexibility for future expansion into machine learning models, cloud synchronization, automatic scheduling, and advanced productivity analytics.

Database Design Principles

The database design follows these principles:

1. Data Integrity

The database should maintain accurate relationships between users, tasks, categories, and historical sessions.

Each entity will have a unique identifier to ensure data can be correctly linked and retrieved.

2. Avoid Unnecessary Data Duplication

Calculated values should not be permanently stored if they can be reliably derived.

For example, total task completion time will not be stored directly.

Instead:

Task ID

↓

Task Sessions

↓

Calculate Total Actual Time

This prevents inconsistencies when session data changes.

3. Historical Data Preservation

Historical information is critical because Predictive Planner improves through user behavior.

The database will preserve:

Original predictions
Actual completion times
User estimates
Task characteristics
Completion patterns

This allows the prediction system to evaluate improvement over time.

4. Future Scalability

The schema will support future expansion while avoiding unnecessary complexity during the MVP.

The design philosophy is:

Design the schema for future growth, but only implement tables required for the current roadmap.

Drift and SQLite were selected because:

Task relationships naturally fit a relational structure.

Name	User display name

Future Expansion

2. User Preferences Table
Purpose

Stores personalized settings that influence scheduling recommendations.

Fields
Field	Description
User ID	Associated user
Preferred Working Hours	Time periods where user prefers working
Productivity Goals	User objectives
Purpose in Prediction System

Preferences help personalize recommendations.

Example:

A user who prefers morning work may receive:

3. Tasks Table
Purpose

The Tasks table is the central entity of Predictive Planner.

It stores active tasks, user estimates, system predictions, scheduling information, and task status.

Fields
Field	Description
Task ID	Unique task identifier
User ID	Task owner
Category ID	Associated category
Task Name	Name of task
User Estimated Duration	User's original estimate
Predicted Duration	System-generated prediction
Deadline	Task deadline
Priority	Importance level
Difficulty	Task difficulty rating
Notes	Additional information
Scheduled Start Time	Calendar start time
Scheduled End Time	Calendar end time
Status	Current task state
Task Status Values

Tasks may have the following states:

Scheduled

↓

In Progress

↓

Completed

↓

Archived

Additional states:

Cancelled
Deleted
Prediction Storage Decision

The original predicted duration will be stored.

Example:

When task is created:

User Estimate:

3 hours


Prediction:

5 hours

The system stores:

Predicted Duration = 5 hours
Reason

This allows the application to measure improvement.

Example:

Initial model:

Prediction Error:
40%

Future model:

Prediction Error:
10%

The user can see improvement over time.

4. Task Sessions Table
Purpose

Stores individual work sessions associated with a task.

Instead of storing one total completion time, Predictive Planner records each session.

Example

Task:

Complete CS Project

Sessions:

Monday:
2 hours

Tuesday:
1.5 hours

Wednesday:
2 hours

Total:

5.5 hours

The total is calculated from sessions.

Fields
Field	Description
Session ID	Unique session identifier
Task ID	Associated task
Start Time	Session start
End Time	Session completion
Duration	Session length
Timer Recovery

If a timer is interrupted:

Example:

Start:
9:00 AM

End:
NULL

The session remains stored.

However, incomplete sessions will not be used for prediction training unless the user manually provides the final duration.

5. Categories Table
Purpose

Stores task categories and metadata used for personalization.

Categories are separated into their own table instead of simple text fields to allow additional intelligence.

Fields
Field	Description
Category ID	Unique identifier
User ID	Category owner
Category Name	Category title
Description	Category meaning
Average Difficulty	Category difficulty trends
Prediction Weight	Future model adjustment value
Example
Programming

Description:
Software development tasks

Prediction tendency:

Final Database Philosophy

Predictive Planner's database is designed around one principle:
